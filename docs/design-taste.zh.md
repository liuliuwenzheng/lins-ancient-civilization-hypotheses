# 设计品味

[English](design-taste.md) | 中文

> 取自 Paul Graham《[Taste for Makers](http://www.paulgraham.com/taste.html)》与乔布斯式工艺：看见的与看不见的都要过关。产品核心仍是**档案 + 只读 API**；文案与 `/ui` 只是呈现层——不能替代可引用的结构。

部分灵感来自公开编译 Graham 一文的帖子（[Jaden_riku / X](https://x.com/Jaden_riku/status/2108876904002670873)）。致敬原文；勿整篇粘贴受版权保护文字。

## 我们在设计什么

| 层 | 职责 | 美感意味着 |
|----|------|------------|
| **档案** | JSON 包 + schema + 出处闸门 | 诚实 ID、事实失败即关闭、无装饰字段 |
| **接口** | 只读 `/api/v1/…` | 清晰信封、稳定形状、假说标签无法绕过 |
| **呈现** | README、文档、`/ui` | 字体、克制、双语清楚——**不上伪造文物图** |

维基赢在覆盖面。我们赢在**可检验的档案工艺**：数据里与屏幕上都做到事实 ≠ 假说。

## 原则（创作者品味 → 本项目）

1. **简单** — 少而真的表面，胜过掩饰薄结构的装饰。
2. **解决对的问题** — 产品是可引用档案 + API，不是更漂亮的百科短文。
3. **辛苦却显得轻松** — 密集出处与闸门藏在平静的 UI 与短路径 README 之后。
4. **一致** — 同样的双语名、同样的 `kind`（`fact` / `hypothesis`）、同样的分页字段。
5. **克制** — 一个强调色；留白充足；无库存「文物」图；无假羊皮纸纹理。
6. **诚实** — 事实与假说必须在**视觉与结构**上显而易见。假说徽章不是可有可无的装饰。
7. **不做装饰性谎言** — 不为填空白而编造坐标、页码、博物馆照片或「秘密档案」。
8. **再设计** — 当更密的档案包或更清晰的 API 信封让旧呈现失真时，迭代。
9. **表里如一** — 乔布斯：柜子背面也要讲究。Schema、`export_check.py`、加载错误同样是工艺。

## 检查清单

### README（中英）

- [ ] 首行语言切换：`English | [中文](…)` / `[English](…) | 中文`
- [ ] 方法表之前先有一行使命
- [ ] 简短 **为何不是维基百科**（诚实：覆盖更窄，机读诚信更强）
- [ ] 简短 **试用 API / UI**，给出确切本地命令——不是营销空话
- [ ] 链接设计品味、架构、档案模型
- [ ] 无伪造图；免责声明仍在

### API JSON 信封

- [ ] 列表响应保持 `{ items, total, count, limit, offset, has_more }`
- [ ] 主张始终暴露 `kind`；假说保留 disclaimer（若有）
- [ ] 主张上的 `sources` 展开为含 `id`、`reliability_tier`、`citation`、`url` 的引用
- [ ] 对外载荷去掉内部 `_pack` / 私有键
- [ ] 根路径 `/api/v1/` 原则优先，并指向 `/ui` 与健康检查

### `/ui` 档案浏览

- [ ] 博物馆级克制：优秀字体、留白、**一个**强调色
- [ ] 中英切换（可持久化偏好）
- [ ] 深浅色跟随 `prefers-color-scheme`（可选手动覆盖）
- [ ] 流程：文明 → **档案报告（分栏）** / 遗址 / 分期 / 主张（报告为默认）
- [ ] 主张 **kind 徽章** 视觉上醒目（`fact` vs `hypothesis`）
- [ ] 每条主张下来源可展开
- [ ] 轻度搜索 / 筛选；移动端友好
- [ ] 研究史与已登记来源脉络可见（不编造考察叙事）
- [ ] **零**库存或伪造文物图——结构与字体承载美感
- [ ] 自包含于 `api/static/`；与 API 同进程提供

### 文档

- [ ] 双语对采用 DeepSeek-Bot 式语言切换
- [ ] 决策注明日期；架构文简要链到设计品味
- [ ] 优先链接来源，勿整篇粘贴受版权保护正文

## 非目标

- 与维基比页面数量
- 用未核验器物照片堆「博物馆画廊」
- 夸大覆盖面或确定性的营销文案
